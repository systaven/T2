# 评论区界面调整

设计检查采用 [Vercel web-design-guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines)：简化评价按钮，统一表单层级，补充可访问标签、键盘焦点、表情名称及关闭入口。样式集中在 `components/NativeComments.module.css`，沿用当前主题颜色变量，不改变评论数据结构。

默认评价图标与表情选择器改用 [Waline 的 B 站小黄脸包](https://github.com/walinejs/emojis)，固定资源版本 `@waline/emojis@1.4.0/bmoji`，从公共 CDN 加载，不需要自己的文件服务器。默认提供 24 个常用表情，已有的后台自定义表情配置仍然生效。评价的五个 ID 不变，旧评价统计无需迁移。图片版权归各自原作者；未将其宣称为本站原创。

游客头像按 [Gravatar 规则](https://docs.gravatar.com/rest/hash/) 对邮箱去首尾空格、转小写并计算 SHA-256，图片网址不包含邮箱原文。编辑器在停止输入 300ms 后更新头像；未填邮箱时显示默认人物头像，图片加载失败时回退到名字首字。头像请求会将邮箱摘要交给第三方头像服务，摘要并不等于完全匿名，不应宣传为完全无关联。

历史游客评论在读取时用已有的私有邮箱字段生成头像地址，不需要修改旧行或数据库结构，公开响应仍不返回邮箱。已登录用户保留自己的账号头像。

公开接口及前台统一过滤基础设施、数据库和认证内部错误；服务器日志保留诊断信息。管理员界面的配置说明不在此次去术语范围。发布成功后的列表刷新不再清除成功提示。

本轮没有实际发布/删除评论，也没有修改数据库中的设置或历史数据。

验证：10 项评论相关单元测试通过，生产构建通过；浏览器检查了桌面、390px 手机及暗色布局，默认评价图标和 24 个选择器表情均成功加载，表情插入正常。手机端五个评价按钮保持一排、表单无横向溢出。公开评论读取不再等待登录服务初始化；状态未确认时，发布和评价等写入仍然阻止执行。

本地缺少数据库服务密钥，实际列表请求显示友好的失败提示，未验证真实评论发布、读取及删除流程。
